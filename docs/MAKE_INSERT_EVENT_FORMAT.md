# Make.com - Insert Event Module Configuration

## ❌ The Problem

If you're getting this error:
```
Request failed with status code 409
{"code":"23503","details":"Key is not present in table \"sources\".","hint":null,"message":"insert or update on table \"events\" violates foreign key constraint \"fk_events_source_id\""}
```

**The issue:** You're sending a `source_id` field that doesn't exist in the `sources` table, or the value is invalid.

## ✅ The Solution

**Do NOT send `source_id` when inserting events from Make.com.** Leave it out entirely or set it to `null`.

---

## Correct Make.com HTTP Module Configuration

### Module: HTTP - Make a Request

**URL:**
```
https://YOUR-PROJECT.supabase.co/rest/v1/events
```

**Method:** `POST`

**Headers:**
| Key | Value |
|-----|-------|
| `apikey` | Your Supabase anon key or service_role key |
| `Authorization` | `Bearer YOUR_SUPABASE_KEY` |
| `Content-Type` | `application/json` |
| `Prefer` | `return=representation` |

**Body Type:** Raw

**Body (JSON):**
```json
{
  "title": "Event Title Here",
  "description": "Event description...",
  "start_time": "2025-12-15T19:00:00-05:00",
  "end_time": "2025-12-15T22:00:00-05:00",
  "venue_name": "Venue Name",
  "neighborhood": "Brooklyn",
  "city": "New York",
  "source_event_url": "https://example.com/event-page",
  "created_via": "import"
}
```

---

## Field Reference

### Required Fields
- **`title`** (text) - The event name

### Optional Fields
- **`description`** (text) - Event description
- **`start_time`** (timestamptz) - Event start date/time (ISO 8601 format)
- **`end_time`** (timestamptz) - Event end date/time (ISO 8601 format)
- **`venue_name`** (text) - Name of the venue
- **`neighborhood`** (text) - NYC neighborhood (e.g., "Williamsburg", "Lower East Side")
- **`city`** (text) - City name (defaults to "New York")
- **`source_event_url`** (text) - Original URL where event was found
- **`created_via`** (text) - How the event was created
  - Options: `'manual'`, `'newsletter'`, `'import'`, `'other'`
  - Default: `'manual'`

### ⚠️ Fields to OMIT (Don't Send These)
- ❌ **`source_id`** - This is automatically set later when sources are discovered. Omitting this field is what fixes the 409 error!
- ❌ **`id`** - Auto-generated by database
- ❌ **`created_at`** - Auto-generated by database
- ❌ **`updated_at`** - Auto-generated by database

## Example: Inserting from a CSV/Spreadsheet

If you're importing events from a CSV or Google Sheets, map your columns like this:

**Make.com Module Mapping:**
```json
{
  "title": "{{1.EventName}}",
  "description": "{{1.Description}}",
  "start_time": "{{formatDate(1.StartDate; 'YYYY-MM-DDTHH:mm:ssZ')}}",
  "end_time": "{{formatDate(1.EndDate; 'YYYY-MM-DDTHH:mm:ssZ')}}",
  "venue_name": "{{1.Venue}}",
  "neighborhood": "{{1.Neighborhood}}",
  "source_event_url": "{{1.URL}}",
  "created_via": "import"
}
```

**Important:** Replace `{{1.FieldName}}` with your actual Make.com variable names.

## Date/Time Format

Make sure dates are in ISO 8601 format with timezone:

### Correct Formats:
```
"2025-12-15T19:00:00-05:00"  ✅ (with timezone offset)
"2025-12-15T19:00:00Z"       ✅ (UTC)
"2025-12-15T19:00:00.000Z"   ✅ (UTC with milliseconds)
```

### Incorrect Formats:
```
"12/15/2025 7:00 PM"         ❌
"2025-12-15"                 ❌ (date only, no time)
"19:00:00"                   ❌ (time only, no date)
```

### Make.com Date Formatting

Use the `formatDate()` function in Make.com:
```
{{formatDate(1.YourDateField; "YYYY-MM-DDTHH:mm:ssZ")}}
```

## Common Errors and Fixes

### Error 409 - Foreign Key Constraint
```json
{"code":"23503","message":"insert or update on table \"events\" violates foreign key constraint \"fk_events_source_id\""}
```
**Fix:** Remove `source_id` from your request body or set it to `null`

### Error 401 - Unauthorized
```json
{"code":"42501","message":"new row violates row-level security policy for table \"events\""}
```
**Fix:**
1. Make sure you ran the migration `009_allow_anon_insert_events.sql` in Supabase SQL Editor
2. Or use the `service_role` key instead of `anon` key

### Error 400 - Invalid JSON
```json
{"message":"Invalid JSON"}
```
**Fix:** Check your JSON syntax - make sure all quotes are correct and fields are comma-separated

### Error 400 - Invalid Date Format
```json
{"code":"22007","message":"invalid input syntax for type timestamp with time zone"}
```
**Fix:** Use ISO 8601 format: `YYYY-MM-DDTHH:mm:ssZ` (see Date/Time Format section above)

## ✅ Checklist

Before running your Make.com scenario:

- [ ] URL points to `/rest/v1/events` (not `/functions/v1/...`)
- [ ] Method is `POST`
- [ ] Headers include `apikey` and `Authorization`
- [ ] Body is valid JSON
- [ ] `source_id` is NOT in the body (or is set to `null`)
- [ ] Dates are in ISO 8601 format
- [ ] `created_via` is one of: `manual`, `newsletter`, `import`, or `other`
- [ ] You've applied the RLS migration `009_allow_anon_insert_events.sql`
